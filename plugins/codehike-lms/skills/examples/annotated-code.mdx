## Annotated code blocks

A fence's meta line carries an optional title that renders in a header bar above the code, written first, plus an optional flag cluster of one `-`-leading token after it. The block below uses the title main.js with flags n+c (line numbers, copy button); writing the flags before the title would leave them visible inside the header bar text. Inline highlighting works anywhere in prose; write *js `greet("world")`* to get a highlighted chip instead of a plain one.

```js main.js -nc
function greet(name) {
  return "Hello, " + name;
}

console.log(greet("world"));
```

### Highlighting lines and tokens

Block annotations take a line range (or apply to the next single line); inline annotations take a regex. Both are stripped from the output; your ordinary comments stay exactly where you wrote them.

```js
// !tooltip[/items/] "A plain array of numbers."
const items = [3, 1, 2]; // !mark gold
// The array is ordinary; order does not matter yet.
const sorted = [...items].sort();
sorted.push(4);
```

This block shows all three comment kinds at once: the plain comment ("The array is ordinary...") stays visible in the output; `!mark gold`, written as a trailing comment on its code line, tints that line with a left accent border and is then removed; and `!tooltip`, written on its own line above where it matches, attaches a hover explanation to the underlined token before being removed itself. Hovering that token shows the tooltip about 300ms later.

### Numbering steps and parts of code

```js
// !pill[/fetchJson/] 1
const data = await fetchJson(url);
// !pill[/filter/] 2
return data.filter(isValid);
```

`!pill[/token/] n` wraps a token in a small tinted chip numbered by `n` (1-6), the color coming from a fixed six-color palette. Use it to label steps or parts of code in order ("first this, then that") and reference those numbers from prose without adding extra markup.

### Folding boilerplate and collapsing regions

```js
// !fold[/(options = \{.*\};)/m]
const options = { timeout: 5000, retries: 2 };
fetchJson("/api/items", options);

// !collapse(1:4) collapsed
function normalize(obj) {
  obj.id = String(obj.id ?? "");
  return obj;
}
```

The `!fold` regex captures the whole options assignment and hides it behind a small expandable button, keeping the call that matters readable. The `!collapse` region starts closed: only its first line (the function signature) stays visible with a chevron, and clicking it reveals or hides everything else in range — here that is the whole body including the closing brace; narrow the range by one line if you would rather leave the brace on screen.

### Showing an edit in place

```js
// !diff -
app.use(legacyLogger());
// !diff +
app.use(structuredLogger());
```

Lines marked with `!diff -` read as removed (red, minus gutter) and lines marked with `!diff +` as added (green). Together they show a change the way a diff view does, without leaving the block.

### Tracing a symbol across a block (code mentions)

<CodeMentions>
The [base case](hover:one) returns 1 directly; the [recursive case](hover:two) multiplies by the result of calling itself again. While either mention above is hovered or keyboard-focused, only its tagged lines stay lit — every other line in this block recedes to low opacity. Clicking a mention does nothing by design.

```js
function factorial(n) {
  if (n === 0) {
    // !mention one
    return 1;
  } else {
    // !mention two
    return n * factorial(n - 1);
  }
}
```
</CodeMentions>

`<CodeMentions>` groups mention links and the fences they point at: write ordinary markdown links whose href starts `hover:` in the prose, and tag target lines inside those fences with a `!mention <id>` comment (its own line directly above, or trailing on the code line). The id after `!mention` must match the text after `hover:` exactly. Fences without any `!mention` tag are not part of the group and never dim; mention links outside a `<CodeMentions>` wrapper render as inert chips that highlight nothing.
